Selected Projects

AACRAO pilot · In testing with registrars

Layout library

Transcript Parser

An application that converts academic transcript PDFs from any institution, digital or scanned, into structured data, verifies that credits and GPAs reconcile, and produces a 1EdTech CLR 2.0 credential and a readable HTML transcript. Developed with a collaborator for an AACRAO pilot, it runs on the issuing institution's own computer, where the results remain.

Extraction
Known transcript layouts are parsed locally by rule-based layout recipes at no cost; unfamiliar layouts are read by a large language model through the Claude API, with automatic re-checks when validation fails.
Layout learning
The application learns a reusable layout from each new format. A layout is saved only after it reproduces the model's reading exactly and is screened for student information.
Integrity
Layouts are distributed through a public library with SHA-256 fingerprints and a digitally signed index; the application accepts only lists signed by trusted keys.
Privacy
An offline mode reads PDFs with layout recipes only, so nothing leaves the computer. The shared library contains formats only, never student data.
Delivery
Local Flask web application and command-line interface, packaged for Windows, macOS, and Linux through a GitHub Actions release workflow.
Quality
449 automated tests, including suites for signature verification, layout-learning safety, and web security; evaluated on 45 sample transcripts at an average of about $0.33 per AI-read transcript.

Python · Flask · Claude API · 1EdTech CLR 2.0 · Digital signatures · GitHub Actions

Application source is private during the pilot; the layout library is public.

Mixture-of-Experts Inference on Consumer GPUs

An inference engine that runs mixture-of-experts language models of up to 80 billion parameters at their original FP8 precision on a single 12–24 GB consumer GPU.

Accuracy
Matched the unrestricted model on HumanEval (152/164 vs. 151/164) with frozen weights and no fine-tuning; fidelity to the native model verified with KL-divergence evaluation.
Performance
Approximately 26 tokens/s on a 30B model and 21 tokens/s on an 80B model using an RTX 4070 (12 GB).
Engineering
Custom FP8 GPU kernels written in Triton, with performance work using torch.compile and CUDA graphs.
Validation
More than 150 tests verify output against the reference Hugging Face transformers implementation across six model families on CPU and GPU.
Delivery
Roughly 230 experiments in the research phase, followed by a rewrite into an installable package with a command-line interface for planning, chat, generation, benchmarking, and evaluation.

Python · PyTorch · Triton · CUDA · Hugging Face Transformers
